# RICA 审计整改路线图 R1.0

基线：`c3749018a61132aecf1a2db0a3fcdc47af723493`

## 执行原则

- 先冻结版本和验证证据，再开展大规模整改。
- 安全授权问题优先于 UI/功能扩展。
- 不以测试数量代替测试覆盖质量。
- 每个整改任务必须包含源码路径、责任模块、风险、测试和退出条件。
- 不自动提交、推送、合并或发布；由项目负责人审核后执行。

## Phase 0：当前 HEAD 验证基线

目标：确认审计基线真实质量，避免将历史问题与现状混淆。

任务：
1. 在干净工作区检出审计 commit。
2. 执行 Rust workspace tests、Clippy、fmt、构建。
3. 执行前端 test、build、lint、UI reuse 检查。
4. 执行 Sidecar 与 Python/Rust 全量契约对拍。
5. 执行 Cargo/npm 依赖安全扫描。
6. 执行 Tauri Host/Sidecar 构建；记录目标平台与工具链。
7. 归档命令、退出码、日志、测试摘要和 commit SHA。

交付物：当前 HEAD 全量测试报告、契约差异报告、依赖扫描报告。

退出条件：所有门禁均有可复核结果；失败项转入缺陷台账，不得隐藏或仅以“环境问题”关闭。

## Phase 1：身份认证与资源级授权

目标：形成可证明的 MultiUser 安全边界。

任务：
1. 建立实体授权矩阵：Position、Candidate、Conversation、Message、Draft、Follow-up、Browser、Share 及其关联实体。
2. 为每个实体定义 Tenant、Owner、Role、Share 访问策略。
3. Application Use Case 显式接收 RequestContext/Scope。
4. Repository 的受保护读写接口强制携带 Scope；禁止普通路径绕过过滤。
5. 对关联 ID 执行归属校验，防止 IDOR/跨租户关联注入。
6. 覆盖 GET/POST/PATCH/DELETE、批量操作、导入导出和分享撤销。
7. 验证 Token 过期、刷新、吊销、角色变化和 Local/MultiUser 模式边界。
8. 保持非 loopback 监听默认拒绝，直到授权验收完成。

交付物：授权矩阵、架构决策记录、负向测试套件、安全验收报告。

退出条件：所有受保护实体跨租户测试通过；无 Scope 的数据访问路径被静态/架构测试阻断；远程监听策略经独立评审。

## Phase 2：测试工程与业务闭环

目标：验证真实业务路径和故障路径。

任务：
1. 建立招聘主流程 E2E：岗位→候选人→沟通→跟进→AI 草稿→人工审核→复制/发送记录→重启后验证。
2. 增加 HTTP 与 Tauri IPC 用例一致性测试。
3. 增加数据库 Migration 升级矩阵。
4. 增加备份恢复、损坏文件、只读目录、磁盘满和并发启动测试。
5. 修复 Browser POC 测试跳过项，覆盖进程启动、超时、清理、崩溃恢复。
6. 将 E2E 和关键集成测试纳入 CI，提供稳定隔离数据。

交付物：E2E 测试计划、自动化测试套件、故障注入报告。

退出条件：核心主路径和关键失败路径可在 CI 重复运行；无未解释的 skip。

## Phase 3：桌面产品化

目标：验证可安装、可升级、可恢复、可追溯。

任务：
1. 构建并记录 Windows 安装制品。
2. 验证全新安装、首次启动、Sidecar 生命周期和端口冲突。
3. 验证旧版本升级、数据库迁移失败回滚和用户数据保留。
4. 验证备份、恢复、卸载与重装。
5. 验证 Keyring/凭据存储权限与故障回退。
6. 完成签名、SHA256、版本和 commit 关联。

交付物：Windows 验收报告、制品清单、签名与校验和记录。

退出条件：目标平台验收矩阵通过；安装包可追溯至源代码 commit。

## Phase 4：工程质量治理

目标：降低长期维护成本。

任务：
1. 分 crate 收紧 missing_docs、unwrap_used、expect_used。
2. 统一错误类型和错误上下文，避免边界层泄露内部信息。
3. 治理 UI 状态词表、共享组件和页面重复实现。
4. 修复 README 与架构/验收文档漂移。
5. 将审计报告、缺陷台账、ADR 和测试报告绑定版本基线。
6. 对每个版本建立“实现状态、测试状态、产品验收状态”三态清单。

交付物：Rust 质量基线、UI 治理报告、文档一致性检查。
